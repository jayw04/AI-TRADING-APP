## 1. The gap

The Observation 1 commit was conditionally authorized against the reviewed pre-commit package
`22b14ff3…`. The authorization required the commit to **fail closed if the committing run would
produce a different outcome than the reviewed one** — but the commit boundary lives inside
`ForwardSessionRunner.run_session`, downstream of the runner's own
`ForwardEvaluator.evaluate_session` call, and the runner had no mechanism to compare its outcome
against an expectation. The reviewed `SessionOutcome` exists only as sealed digests; the record is
append-only. A divergence could therefore only be **detected after** an irreversible write, never
**prevented before** it. Option A (commit, then verify) was considered and **not authorized**.

## 2. The mechanism

`FirstSessionOutcomePin` — session date, `sealed_performance_sha256`, `input_evidence_digest`, and
the identity of the reviewed package they were read from. The runner still evaluates internally,
exactly as it always has. Immediately before `open_first_window_session` — after the sealed payload,
the decision evidence, the store-unchanged proof and the Account-4-unchanged proof — the newly
produced outcome is compared against the pin. A mismatch stops **before** the committing call,
before any sequence allocation, before `commit.json`, and before the post-commit durable ledger
save.

**The pin narrows; it never supplies.** It carries digests of the reviewed outcome, not the outcome
itself — no holdings, no returns, no census. The committed record is built from the outcome the
committing run produced; the pin can only refuse it. "Commit the reviewed outcome" cannot decay into
"commit what the operator typed".

An immutable receipt (`outcome_pin_receipts.jsonl`, store root, fsynced like the stop log) records
expected and actual side by side on **both** outcomes — the receipt of a match is the evidence that
the committed observation is the reviewed one.

## 3. Fail-closed inventory

| condition | behaviour |
|---|---|
| declared pin with a missing/malformed digest | configuration REFUSED at load — never degrades to unpinned |
| pin session ≠ run session | STOP `OUTCOME_PIN_SESSION_MISMATCH`, before any data work |
| record already holds observations | STOP `OUTCOME_PIN_ALREADY_COMMITTED` — the approval was consumed |
| sealed-performance digest differs | STOP `OUTCOME_PIN_MISMATCH`, nothing committed |
| input-evidence digest differs | STOP `OUTCOME_PIN_MISMATCH`, nothing committed |
| no evidence-binding provider | STOP `OUTCOME_PIN_EVIDENCE_UNAVAILABLE` — half a comparison is none |
| Account 4 moves during the run | existing STOP, unchanged — checked before the pin |
| expectations via environment | impossible — configuration file only; AST-pinned by test |

Unpinned operation is byte-for-byte the ordinary runner path, and writes no receipt.
